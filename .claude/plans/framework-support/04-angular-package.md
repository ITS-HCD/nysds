# WS4: `@nysds/angular`

**Goal:** A published `@nysds/angular` package where every component is a typed Angular component, every form component works with `ngModel`, Reactive Forms, and Signal Forms, and consumers never write `CUSTOM_ELEMENTS_SCHEMA`.
**Depends on:** WS1, WS2, decision R2.
**Owns:** `packages/angular/**` (hand-written scaffolding and form base classes), the Angular template in `packages/codegen/src/cem-plugins/angular.mjs`.
**Branch:** `feat/fw-4-angular`.
**Reference:** `.claude/plans/framework-support/prior-art/angular-support/` (Eric's CVA base, event types, smoke tests). Reuse its ideas; regenerate its code.

## Why Angular is the hard one, and what each part of this design answers

| Reported pain | Root cause | Design answer |
|---|---|---|
| `ngModel` / `formControlName` throws "No value accessor for form control" | Angular's `DefaultValueAccessor` only matches `input`, `textarea`, `select`; the real input is in shadow DOM and no native `input`/`change` reaches the host | A `ControlValueAccessor` per form component, listening to `nys-change`/`nys-input`, writing the `value`/`checked`/`files` property |
| Every template needs `CUSTOM_ELEMENTS_SCHEMA`, and then every binding is unchecked | Angular doesn't know the element | The wrapper is a `@Component` with the tag as selector. The element becomes known; inputs and outputs are typed; typos are compile errors |
| `$event` is `Event`, not the detail | Native event binding has no type info | Typed outputs: `(nysChange)="onChange($event)"` where `$event: NysSelectChangeEvent` |
| `[disabled]` from `FormControl` doesn't propagate | No CVA `setDisabledState` | Base class implements it |
| Validation shows twice or never | Component has its own `required` UI via ElementInternals; Angular has its own errors; nothing connects them | Opt-in `nysControlErrors` directive maps Angular errors → `showError`/`errorMessage`; README documents "let Angular own validation" vs "let the component own it" |
| Group controls (`radiogroup`, `checkboxgroup`) have no bindable value | No public `value`, no group event | WS1 adds both; the CVA binds at group level |
| OnPush / zoneless components don't re-render on custom events | Events fired outside Angular's knowledge | Outputs are re-emitted through `output()` inside the component; zoneless works because `OutputEmitterRef` triggers change detection on the subscribing view |
| Angular SSR hydration mismatch warnings | Custom elements render client-side | README: `ngSkipHydration` on containers, or `provideClientHydration` with the component registered client-only |

## Generated component template

`packages/angular/src/generated/nys-textinput.component.ts` (form component):

```ts
// GENERATED by @nysds/codegen — do not edit. Override: src/overrides/nys-textinput.component.ts
import { ChangeDetectionStrategy, Component, ElementRef, HostListener, inject, Input, output, forwardRef } from "@angular/core";
import { NG_VALUE_ACCESSOR } from "@angular/forms";
import "@nysds/nys-textinput";
import type { NysTextinput, NysTextinputInputEvent, NysTextinputChangeEvent } from "@nysds/nys-textinput";
import { NysValueAccessor } from "../lib/forms/value-accessor";

@Component({
  selector: "nys-textinput",
  standalone: true,
  template: "<ng-content></ng-content>",
  changeDetection: ChangeDetectionStrategy.OnPush,
  providers: [{ provide: NG_VALUE_ACCESSOR, useExisting: forwardRef(() => NysTextinputComponent), multi: true }],
})
export class NysTextinputComponent extends NysValueAccessor<string> {
  protected override readonly el: ElementRef<NysTextinput> = inject(ElementRef);
  protected override readonly changeEvent = "nys-change";
  protected override readonly inputEvent = "nys-input";

  /** Field label. */
  @Input() set label(v: string) { this.el.nativeElement.label = v; }
  get label(): string { return this.el.nativeElement.label; }

  /** Marks the field required. */
  @Input({ transform: booleanAttribute }) set required(v: boolean) { this.el.nativeElement.required = v; }
  get required(): boolean { return this.el.nativeElement.required; }

  // ... one setter/getter pair per public property from the manifest

  readonly nysInput = output<NysTextinputInputEvent>();
  readonly nysChange = output<NysTextinputChangeEvent>();
  readonly nysFocus = output<Event>();
  readonly nysBlur = output<Event>();

  @HostListener("nys-input", ["$event"]) protected _onNysInput(e: NysTextinputInputEvent) { this.nysInput.emit(e); this.handleInput(e); }
  @HostListener("nys-change", ["$event"]) protected _onNysChange(e: NysTextinputChangeEvent) { this.nysChange.emit(e); this.handleChange(e); }
  @HostListener("nys-focus", ["$event"]) protected _onNysFocus(e: Event) { this.nysFocus.emit(e); }
  @HostListener("nys-blur", ["$event"]) protected _onNysBlur(e: Event) { this.nysBlur.emit(e); this.handleBlur(); }
}
```

Non-form components use the same template without the `providers`, the base class, or the `handle*` calls.

Template rules the plugin follows:
- Property setters write to the element (`this.el.nativeElement[prop] = v`). Getters read back so `[(prop)]` two-way binding works where a matching `<prop>Change` output exists. Use `Renderer2` only if a reviewer asks; direct property assignment on the host element is standard for proxy components and is what Ionic ships.
- Boolean props use `{ transform: booleanAttribute }` so `<nys-textinput required>` and `[required]="true"` both work. Numbers use `numberAttribute`.
- Input types come from the manifest `type.text`. Unions stay unions. Anything the plugin can't parse becomes `unknown` and logs a warning listing the component and property; the build fails if the warning count grows (guard against silent `any` creep).
- Outputs use the `output()` function, not `EventEmitter`, so they're zoneless-safe. `@HostListener` re-emits. Output names follow `README.md` section 4.1.
- Members skipped: `@internal`, `@deprecated`, leading underscore, static, `updateComplete`, and any name that collides with an `HTMLElement` property already handled by Angular (`id`, `title`, `hidden`, `tabIndex`, `className`, `style`). `id` needs care: components declare `id` as a reflected property; Angular sets the attribute itself, and the reflected property picks it up, so skip it in the wrapper.
- Sub-components (`nys-option`, `nys-accordionitem`, `nys-tab`, `nys-step`) get wrappers too, so they're known elements and get typed inputs.

## Hand-written form base classes (`src/lib/forms/`)

```
value-accessor.ts     NysValueAccessor<T>: CVA for kind "value"; writeValue sets el.value; handleChange/handleInput read detail.value; handleBlur → onTouched; setDisabledState sets el.disabled
checked-accessor.ts   NysCheckedAccessor: kind "checked"; writes el.checked; reads detail.checked
files-accessor.ts     NysFilesAccessor: kind "files"; writeValue calls el.setFiles(files ?? []); reads el.files after nys-change
control-errors.directive.ts   nysControlErrors (opt-in, see Validation)
error-messages.token.ts       NYS_ERROR_MESSAGES: InjectionToken<Record<string, (err: unknown) => string>> with defaults for required, minlength, maxlength, pattern, email, min, max
```

The plugin picks the base class by `formControl.kind` from the manifest. `inputEvent` is optional; when present the accessor updates the model on `nys-input` (live) and marks dirty; `nys-change` is always handled (covers programmatic and discrete changes). Base class guards against echo: `writeValue` sets a flag so a `nys-change` fired synchronously by the component in response to a property write is ignored (WS1 says components shouldn't fire on programmatic set; this is belt and braces).

`writeValue(null | undefined)` writes the kind's empty value (`""`, `false`, `[]`), matching what `FormControl.reset()` sends.

## Validation

Two supported modes, documented side by side:

**Component-owned (default, zero config).** The component validates with ElementInternals and shows its own `required`/`pattern` errors on blur. Angular validators still run for form-level validity (`form.invalid`), and `required` on the element also registers Angular's `RequiredValidator` because its selector matches `[required][formControlName]` on any element. Two validators, one visible message, consistent because both are `required`.

**Angular-owned (opt-in).** `<nys-textinput formControlName="email" nysControlErrors>`. The `NysControlErrorsDirective` injects `NgControl`, subscribes to `statusChanges` and `touched` transitions, and sets `showError` and `errorMessage` on the host from `control.errors` via `NYS_ERROR_MESSAGES`. It sets `errorMessage` only from Angular errors and clears it when valid, and it never touches the component's internal validation text (WS1's precedence rule makes that safe). Consumers override messages by providing `NYS_ERROR_MESSAGES`.

Signal Forms: `[formField]` binds through the same CVA (Angular's interop). Verify on Angular 21 and 22 in `examples/angular-app`. Record in the README which Signal Forms features work through CVA (value, disabled, touched) and which don't (required/min/max propagation from the schema to the element; those are `FormValueControl`-only). A `FormValueControl` adapter is a follow-up, listed in WS8 as v1.x enhancement, not a blocker.

Secondary entry points: `@nysds/angular/textinput` etc. ng-packagr supports them through nested `package.json` files or `ng-package.json` `secondaryEntryPoints` (ng-packagr ≥ 18 supports the latter). `deps.mjs` (WS2) writes the list. Verify the built `dist/` has `fesm2022/nysds-angular-textinput.mjs` per entry.

`private: true` on the source `package.json` with `strip-private.mjs` after build, or better: publish from `dist/` explicitly in the release script and never rely on `npm publish --workspaces` picking this package. WS8 owns the release script; this WS must make `dist/package.json` publish-ready and add the `npm pack --dry-run` guard to its own build script so the 1.18.2 mistake can't recur.

Angular toolchain versions (R2): devDependencies pinned to the Angular 20 line (`@angular/core@^20`, `ng-packagr@^20`, `typescript` per Angular 20's range). Consumers on 21 and 22 verified in WS5.
